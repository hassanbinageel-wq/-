# متجر «غيمة» لملابس ومستلزمات المواليد

متجر إلكتروني عربي (RTL) كامل مع لوحة تحكم عربية: منتجات وخيارات وباقات هدايا، سلة وطلب كضيف، دفع بالتحويل اليدوي وإرسال السند عبر واتساب، حجز مخزون، تتبع الطلبات، صلاحيات للموظفين، تحكم كامل بالمظهر، ونسخ احتياطي.

> «غيمة» اسم وهوية مؤقتة. غيّر الاسم والشعار والألوان من **لوحة التحكم ← مظهر المتجر** دون تعديل الكود.

---

## التقنيات ولماذا

| الجزء | الاختيار | السبب |
|---|---|---|
| الواجهة والخادم | **Next.js 16 (App Router) + React 19 + TypeScript** | صفحات تُبنى على الخادم (سرعة وSEO)، وواجهات API في نفس المشروع، ونوع بيانات موحد بين المتجر واللوحة |
| قاعدة البيانات | **SQLite** (better-sqlite3) بوضع WAL | ملف واحد دائم، سريع، معاملات حقيقية تمنع البيع الزائد عند الطلبات المتزامنة، ونسخه الاحتياطي بسيط. مناسب لمتجر واحد على خادم واحد |
| الصور | **sharp** | يعيد ترميز كل صورة مرفوعة (WEBP بعدة مقاسات)، ويحذف البيانات المخفية، ويرفض الملفات غير الصالحة |
| التحقق | **zod** | كل مدخلات المتجر واللوحة تُتحقق على الخادم |

كل البيانات (قاعدة البيانات، الصور، السندات الخاصة، النسخ الاحتياطية) في مجلد واحد: `DATA_DIR` (افتراضياً `./data`). لا يُعتمد على المتصفح لحفظ بيانات المتجر أو الطلبات؛ المتصفح يحفظ السلة والمفضلة للزائر فقط.

## التشغيل المحلي

المتطلبات: **Node.js 20.9 أو أحدث** (يُفضل 22).

```bash
cd baby-store
npm ci                      # لا يحتاج أدوات ترجمة (انظر .npmrc)
cp .env.example .env        # عدّل القيم عند الحاجة
npm run db:seed             # اختياري: منتجات وبنرات تجريبية واضحة (قابلة للحذف)
npm run owner:create        # إنشاء حساب المالك (يسأل عن الاسم وكلمة المرور)
npm run build
npm start                   # http://localhost:3000  — اللوحة: /admin
```

للتطوير: `npm run dev`.

عند أول تشغيل تُنشأ قاعدة البيانات تلقائياً مع **هيكل المتجر الأساسي**: صفحات السياسات (من نحن، الشحن، الاستبدال، الخصوصية، طريقة الطلب، تواصل معنا) بصيغة عامة يجب مراجعتها، أسئلة شائعة، الأقسام الخمسة (ملابس المواليد، أطقم المواليد، الإكسسوارات، الهدايا والتغليف، مستلزمات المواليد)، وتصنيفات العمر والمناسبة. لا تُنشأ أي منتجات أو حسابات تحويل.

`npm run db:seed -- --no-demo` لا يضيف شيئاً تجريبياً.

## إنشاء حساب المالك

**الطريقة الأولى (مستحسنة):** من سطر الأوامر على الخادم

```bash
npm run owner:create
# أو بدون أسئلة:
npm run owner:create -- --username owner --name "اسم المالك" --password "كلمة مرور قوية 10 أحرف+"
```

نفس الأمر يعيد تعيين كلمة المرور إن نسيتها (ويُخرج كل الجلسات المفتوحة).

**الطريقة الثانية:** من المتصفح لمرة واحدة. ضع `SETUP_TOKEN` (12 حرفاً على الأقل) في `.env`، أعد التشغيل، وافتح `/admin/setup`. تتوقف هذه الصفحة تلقائياً بعد إنشاء أول حساب، واحذف `SETUP_TOKEN` بعدها.

كلمة المرور: 10 أحرف على الأقل وتحتوي حروفاً وأرقاماً. يُقفل الحساب مؤقتاً بعد 5 محاولات خاطئة.

---

## قبل الإطلاق (قائمة تظهر أيضاً في الصفحة الرئيسية للوحة)

1. **رقم واتساب الطلبات**: لوحة التحكم ← الإعدادات. الافتراضي `775038900` برمز الدولة `967` (أي `+967775038900`، ورابط `wa.me/967775038900`).
2. **وسائل التحويل**: لوحة التحكم ← وسائل التحويل (انظر القسم التالي). بدونها يرى العميل «تواصل مع المتجر للحصول على بيانات التحويل».
3. **مناطق التوصيل ورسومها**: لوحة التحكم ← التوصيل والاستلام. المناطق الحالية (إن شغّلت `db:seed`) تجريبية بأسعار افتراضية.
4. **المنتجات**: أضف منتجاتك، ثم احذف التجريبية من الإعدادات ← البيانات التجريبية (اكتب «حذف» للتأكيد). الطلبات لا تُحذف.
5. **صفحات السياسات**: لوحة التحكم ← الصفحات والأسئلة. النصوص الافتراضية عامة ولا تتضمن مدداً أو التزامات لم تحددها.
6. **الشعار والأيقونة والألوان والخط والبنرات**: لوحة التحكم ← مظهر المتجر (حفظ كمسودة، معاينة جوال/حاسوب، ثم نشر، مع إمكانية الرجوع لنسخة سابقة).
7. **حسابات الموظفين** (اختياري): لوحة التحكم ← المستخدمون والصلاحيات.

---

## إضافة وسائل التحويل

لوحة التحكم ← **وسائل التحويل** ← «إضافة وسيلة»:

- النوع (حساب بنكي / محفظة إلكترونية / شركة صرافة / أخرى)، اسم البنك أو المحفظة، اسم المستفيد، رقم الحساب أو المحفظة، العملة، تعليمات إضافية، صورة QR اختيارية، تفعيل/تعطيل، والترتيب بالسحب.
- تظهر الوسائل المفعّلة في صفحة الدفع بعد الطلب مع أزرار نسخ للرقم والمبلغ.
- المتجر لا يفترض أن رقم واتساب حساب للتحويل، ولا يحتوي أي بيانات مالية تجريبية.

## الخط (DIN Next LT Arabic)

الخط المرفق **ليس ضمن المستودع** لأنه خط تجاري مرخّص ولا يجوز نشره في مستودع عام. لاستخدامه (بعد التأكد أن ترخيصك يسمح باستخدامه على الويب):

- من **لوحة التحكم ← مظهر المتجر ← الألوان والخطوط ← رفع ملف خط** ثم اختر «الخط المرفوع» وانشر، أو
- من سطر الأوامر: `npm run font:import -- ./DINNextLTArabic-Regular.ttf "DIN Next LT Arabic"`

إلى أن يُرفع، يُستخدم خط «تجوال» (رخصة OFL، مضمّن في `public/fonts` مع خطوط المراعي والقاهرة وIBM Plex Sans Arabic).

## النشر على خادم

المتجر يحتاج **خادماً دائماً بقرص دائم** (VPS أو خادم مخصص أو أي منصة حاويات تدعم الأقراص الدائمة). **لا يناسب** الاستضافة بدون خادم (مثل Vercel/Netlify Functions) لأن قاعدة البيانات والصور ملفات محلية.

### الخيار 1: Docker (مجرّب)

```bash
cd baby-store
cp .env.example .env    # اضبط SITE_URL على رابط متجرك https
docker compose up -d --build
docker compose exec store npm run owner:create
docker compose exec store npm run db:seed        # اختياري
```

البيانات في الحجم `store-data` (المسار `/app/data` داخل الحاوية). يستمع على `127.0.0.1:3000` ليكون خلف وكيل HTTPS.

### الخيار 2: Node مباشرة (systemd أو PM2)

```bash
npm ci && npm run build
DATA_DIR=/var/lib/baby-store NODE_ENV=production PORT=3000 npm start
```

اجعل `DATA_DIR` خارج مجلد الكود حتى لا يتأثر بالتحديثات.

### HTTPS (مطلوب في الإنتاج)

ملف تعريف الدخول للوحة مؤمَّن (`Secure`) فلا يعمل الدخول عبر `http` في الإنتاج إلا على `localhost`. ضع المتجر خلف وكيل يوفر شهادة SSL، مثلاً **Caddy** (يصدر الشهادة تلقائياً):

```
shop.example.com {
    reverse_proxy 127.0.0.1:3000
}
```

ثم في `.env`: `SITE_URL=https://shop.example.com` و`TRUST_PROXY=1`.
للتجربة المؤقتة فقط عبر `http` على عنوان IP: `COOKIE_SECURE=0`.

### متغيرات البيئة (`.env`)

| المتغير | الوصف |
|---|---|
| `SITE_URL` | رابط المتجر العام (للروابط وخريطة الموقع ورابط التتبع في رسالة واتساب) |
| `DATA_DIR` | مجلد البيانات الدائم |
| `APP_SECRET` | مفتاح سري عشوائي طويل. إن تُرك فارغاً يُنشأ تلقائياً في `DATA_DIR/.secret`. لا تغيّره بعد الإطلاق (يُستخدم لتوقيع ربط المتصفح بطلبات العميل) |
| `TRUST_PROXY` | `1` خلف وكيل عكسي لقراءة عنوان IP الحقيقي (لحدود المحاولات) |
| `COOKIE_SECURE` | `0` فقط للتجربة بدون HTTPS |
| `SETUP_TOKEN` | لإنشاء المالك من المتصفح لمرة واحدة (اختياري) |

### التحديث

اسحب الكود الجديد، `npm ci && npm run build`، ثم أعد التشغيل (أو `docker compose up -d --build`). تحديثات قاعدة البيانات تُطبق تلقائياً عند التشغيل. خذ نسخة احتياطية قبل كل تحديث.

## النسخ الاحتياطي والاستعادة

- **تلقائي**: نسخة يومية مفعّلة افتراضياً (يُحتفظ بآخر 7) ما دام التطبيق يعمل، الإعداد من لوحة التحكم ← النسخ الاحتياطي.
- **يدوي**: من نفس الصفحة (إنشاء / تنزيل / استعادة)، أو `npm run backup`.
- **مجدول عبر cron** (مثال يومي 3 صباحاً):
  `0 3 * * * cd /path/baby-store && npm run backup -- --keep 14`
- النسخة ملف `tar.gz` يضم قاعدة البيانات وكل الصور والسندات. **انسخها دورياً خارج الخادم** (قرص آخر أو تخزين سحابي)؛ النسخ على نفس الخادم لا تحمي من تلف القرص.
- **الاستعادة** من اللوحة تتطلب كلمة مرور المالك وكتابة «استعادة»، وتتحقق من سلامة الملف، وتأخذ نسخة أمان من البيانات الحالية قبل الاستبدال. من سطر الأوامر (بعد إيقاف التطبيق): `npm run restore -- ./data/backups/backup-....tar.gz`.

## الصلاحيات

| الدور | يستطيع |
|---|---|
| المالك | كل شيء: الإعدادات، وسائل التحويل، التوصيل، الكوبونات، المظهر، التقارير، المستخدمون، النسخ الاحتياطي، سجل الإجراءات |

## الخدمات الخارجية

**لا يحتاج المتجر أي خدمة خارجية مدفوعة أو مفاتيح API ليعمل.**

- **واتساب**: روابط `wa.me` عادية تفتح المحادثة بنص الطلب جاهزاً. لا يوجد ربط بـ WhatsApp Business API، فلا تُرسل رسائل تلقائياً: العميل يضغط «إرسال» بنفسه ويرفق صورة السند يدوياً، والموظف يفتح قوالب الرسائل من اللوحة ويرسلها يدوياً.
- **الدفع**: تحويل يدوي فقط ومراجعة بشرية؛ لا بوابة دفع ولا حقول بطاقات.
- **البريد الإلكتروني / الرسائل النصية**: غير مستخدمة. الإشعارات داخل اللوحة (مع صوت اختياري).
- **الخرائط**: العميل يلصق رابط موقعه اختيارياً؛ لا يُحمّل أي سكربت خرائط.
- **الخطوط**: مستضافة محلياً.

إن رغبت لاحقاً بإشعارات بريدية أو WhatsApp Business API فتلك تتطلب حساباً ومفاتيح من مزود الخدمة وربطاً إضافياً، ولا تعمل حالياً.

## الأمان باختصار

- كلمات المرور مشفرة (scrypt)، الجلسات عشوائية ومخزنة مجزأة، قفل بعد المحاولات الخاطئة، وحدود طلبات لكل IP على الدخول وإنشاء الطلبات والتتبع.
- لا أسرار في الواجهة؛ الأسعار والخصومات والشحن والمخزون تُحسب وتُتحقق على الخادم فقط.
- **سندات التحويل** في مجلد خاص (`uploads/private`) لا يُخدم للعامة؛ تُعرض فقط لمستخدم مسجل الدخول بصلاحية الطلبات أو المدفوعات.
- رابط تتبع الطلب عشوائي يصعب تخمينه، ويُخفي الاسم والهاتف والعنوان جزئياً، ولا يحتوي بيانات شخصية في الرابط.
- الصور المرفوعة يُعاد ترميزها؛ ملفات CSV المصدّرة محمية من حقن المعادلات.
- حماية من الطلبات المكررة (مفتاح لكل محاولة)، حقل خفي ضد الرسائل الآلية، وحد للطلبات المعلقة لكل رقم.

## ملاحظات

- **البيانات التجريبية** (عند تشغيل `db:seed`): منتجات بصور مرسومة، دليل مقاسات، خيارات تغليف، مناطق توصيل، وكوبون `WELCOME10`؛ كلها معلّمة «تجريبي» وتُحذف بأمر واحد. لا تقييمات أو مبيعات أو عدادات وهمية في أي مكان.
- **الخامات وشهادات السلامة وبلد الصنع** لا تظهر إلا إذا أدخلتها بنفسك لكل منتج؛ الحقول الفارغة لا تُعرض.
- العملة الافتراضية الريال اليمني بدون كسور؛ تُغيَّر من الإعدادات.
